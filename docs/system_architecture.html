VALZ on Google Cloud: from factory-floor video to approved Gemba Kaizen action

A clip goes from the browser straight into Cloud Storage. Eventarc starts a Workflows pipeline that normalises the video with the Transcoder API, samples keyframes in a Cloud Run job and counts people with the Video Intelligence API. The Safety Agent asks Gemini on Vertex AI what the worker is doing in each keyframe; the Gemba Kaizen Agent turns the measured waste into action cards, citing a Vertex AI RAG Engine corpus of lean knowledge. Anything Gemini is not sure about goes to the operator through Speech-to-Text and Text-to-Speech, in Thai. State lives in Firestore, analytics in BigQuery. Every box carries its owner (P1–P5) in the delegation section below.

Target architecture. This page describes VALZ running entirely on Google Cloud. In the repository today ai_backend still calls OpenRouter and ElevenLabs and runs BLIP and YOLO itself; the table under What changes in the code lists every swap. Each service is deployed in DEPLOYMENT.md. For the lean version (one Compute Engine VM and Firebase), see DEPLOYMENT_VM.md.

The numbers in the diagram

Request path

  1. 1 · Enter. A person opens https://valz.<domain>. Cloud DNS points at one global IP; Cloud Armor filters the request; the external Application Load Balancer terminates TLS and serves cached static files from Cloud CDN; Identity-Aware Proxy signs managers in with their Google account.
  2. 2 · Serve and sign. The load balancer routes to valz-frontend (SvelteKit). Its /api/* proxy calls valz-api with a service-to-service ID token. For a new clip, valz-api returns a V4 signed URL (signed through the IAM Credentials API), so the video never passes through Cloud Run.
  3. 3 · Upload. The browser PUTs the clip (up to 550 MB) to the raw-clips bucket with a resumable upload. Cloud Run's 32 MiB request limit is the reason uploads bypass it.
  4. 4 · Orchestrate. The object.finalized event reaches Eventarc, which starts the valz-pipeline workflow. The workflow runs the Transcoder API, then the valz-perception Cloud Run job (keyframes and motion energy) and the Video Intelligence person-detection call in parallel, then calls the agents on valz-api.
  5. 5 · See. The Safety Agent sends keyframes and the safety rules to Gemini (multimodal) and gets back segments classed VA, a Muda type, or UNCERTAIN when confidence is under 0.75.
  6. 6 · Suggest. The Gemba Kaizen Engine (plain Python) computes cycle time, VA% / NVA% and projected hours per shift. The Gemba Kaizen Agent retrieves countermeasure cards from Vertex AI RAG Engine and asks Gemini for 2–5 cards in a strict JSON schema. ROI is computed by the engine, never by the model.
  7. 7 · Ask. Each UNCERTAIN segment is published to Pub/Sub (segment.uncertain). The Voice Agent turns it into a short question, speaks it with Text-to-Speech in the operator's language, transcribes the answer with Speech-to-Text and marks the segment verified. Cloud Translation covers fixed labels in the three report languages.
  8. 8 · Remember. Runs, segments, cards, decisions and questions are Firestore documents. valz-api listens to them and streams changes to the dashboard as server-sent events, so the browser never talks to Firestore directly.
  9. 9 · Learn. A Cloud Scheduler job copies approved cards and per-shift metrics into BigQuery. Looker Studio reads the dataset for the plant-wide report.

What changes in the code

TodayOn Google Cloud
openrouter_client.pyA thin google-genai client in Vertex AI mode, authenticated with the service account (no API key). VLM_MODEL and LSS_LLM_MODEL keep their names and take Gemini model IDs.
vlm_action_model.py, safety_agent.pySend keyframes (or the transcoded clip) to Gemini; keep the same segment schema and the 0.75 confidence rule.
person_count_model.py, video_action_model.py (YOLOv8, BLIP)Video Intelligence PERSON_DETECTION. The local models stay available as a fallback, which keeps the API image under 1 GB if they are dropped.
lss_agent.py keyword retrieval over knowledge/lss_cards.jsonRAG Engine retrieval, with lss_cards.json imported as the first corpus file.
voice_agent.py (ElevenLabs, SQLite in /app/data)Text-to-Speech and Speech-to-Text; audio cache in the processed bucket, metadata in Firestore. Cloud Run disks are ephemeral, so nothing may stay in /app/data.
video_convert.py (ffmpeg)Transcoder API job started by the workflow.
/analysis/analyze/upload receives the fileNew POST /api/uploads returns a signed URL; the analysis endpoints accept a gs:// URI instead of a file. Status and results move to Firestore.
Frontend /api/[...path] proxy to AI_BACKEND_URLSame proxy, but it attaches a Google ID token for the valz-api audience and no longer streams the video. Set ALLOW_BACKEND_OVERRIDE=false.
docker-compose.yml, deploy/nginx.confKept for local development. Production uses the load balancer and Cloud Run.

Delegation

One owner per box, one contract per arrow

Band 3 · Ingest & perception

P1

Vision Pipeline Engineer

Services

  • Cloud Storage raw-clips and processed, with CORS for the browser PUT
  • Transcoder API job template (H.264, 720p preview)
  • Cloud Run job valz-perception: keyframes where motion changes plus a steady baseline sample
  • Video Intelligence person detection; map its output to the people-count fields

Contract

IN gs:// clip from raw-clips
OUT keyframes + people count in processed/<run_id>/ → P2

Done when

A 20 s clip becomes keyframes and a people count in under 30 s, and the workflow re-runs the same clip to the same output.

Band 4 · Reasoning

P2

Gemini Prompts, Safety Rules & RAG Corpus

Services

  • Vertex AI Gemini: the vision prompt, with the 7 Muda definitions and the safety rules (helmet, running, phone, person down)
  • Segments under 0.75 confidence stay UNCERTAIN; never guess
  • Vertex AI RAG Engine corpus: countermeasure cards, SOPs, past approved cards
  • JSON-schema validation, one retry, cached verdicts per run for the demo

Contract

IN keyframes + people count from P1
OUT segments (resolved_by gemini or null) → P3

Done when

The demo clip gives the same segments three runs in a row, the blocked-camera moment comes out grey, and the staged no-helmet moment is flagged high.

Bands 2 · 3 · 5 · Core

P3

Backend, Orchestration & Platform

Services

  • Cloud Run valz-api: Gemba Kaizen Engine, agents, SSE, signed-URL endpoint
  • Workflows, Eventarc, Pub/Sub, Cloud Tasks, Cloud Scheduler
  • Firestore data model and BigQuery sync
  • Platform: project and APIs, IAM, Secret Manager, KMS, Artifact Registry, Cloud Build / Deploy, Logging and budgets

Contract

IN segments from P2, answers from P4
OUT cards, alerts and the SSE stream → P4 / P5

Done when

Pushing to main deploys both services, and a clip dropped in raw-clips ends as cards in Firestore with no manual step.

Band 4 · Voice

P4

Voice Agent Engineer

Services

  • Speech-to-Text v2 recognizers for th-TH, ja-JP, en-US
  • Text-to-Speech Chirp 3 HD voices per language
  • Cloud Translation for fixed labels; Gemini for the questions themselves
  • Pub/Sub subscription on segment.uncertain and alert.raised

Contract

IN question or alert from P3
OUT POST /api/agent/verify with answer + root cause

Done when

An UNCERTAIN segment is asked in Thai, answered by voice and shown as verified with the ROI recalculated, in under 20 s.

Bands 1 · 2 · Interface + stage

P5

Dashboard, Edge, Demo & Pitch

Services

  • Cloud Run valz-frontend (SvelteKit)
  • Load balancer, Cloud CDN, Cloud Armor, IAP and DNS
  • Cloud Storage static for demo clips; Looker Studio report
  • Demo clips, backup recording and the 3-minute pitch

Contract

IN cards, segments and SSE from P3
OUT POST /api/cards/{id}/decision

Done when

The public URL works behind sign-in, the cached demo runs with the backend off, and the pitch runs end to end three times without a restart.
