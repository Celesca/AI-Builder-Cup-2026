Architecture · Team Delegation · U-Hackathon AI Track

VALZ: from factory-floor video to approved Gemba Kaizen action

Live camera frames and recorded clips flow left→right through a perception layer, where BLIP labels every frame and Qwen on OpenRouter steps in only as a last resort. Results land in the Gemba Kaizen (Kaizen) Core as waste-classified segments and safety events, then surface top→down through a multilingual ElevenLabs voice agent (it asks, answers and raises safety alerts in the operator's own language) and a SvelteKit dashboard where the operator approves actions. Every box carries its owner (P1–P5).

Delegation

One owner per box, one contract per arrow

Nodes 01 · 02 · Perception

P1

Vision Pipeline Engineer

Tasks

  • Clip mode: FFmpeg decode; OpenCV frame-diff → motion energy; keep keyframes where motion changes + a steady baseline sample
  • Live mode: read the camera stream continuously, sample frames, run safety rules only
  • BLIP captions each keyframe; MiniLM matches captions against P2's label prompts
  • Resolved frames → segments.json to P3; unresolved frames + raw keyframes → P2
  • Batch and cache to disk by clip_id

Contract

IN live stream + MP4 from P5's camera
OUT segments.json (resolved_by blip) → P3 · unresolved → P2

Done when

A 20 s clip becomes labeled segments in under 30 s, and the live sampler keeps up with the camera without falling behind.

Node 03 · Perception

P2

Labels, Safety Rules & Qwen Escalation

Tasks

  • Own the label vocabulary used by both BLIP matching and Qwen: VA / NNVA / NVA waste types + safety rules with severity (helmet, running, phone, person down)
  • Qwen on OpenRouter (default qwen/qwen3.7-flash) runs only on frames BLIP couldn't resolve: keyframe + label prompt → Yes/No verdict
  • If Qwen can't tell either → class UNCERTAIN, status needs_verification. Never guess.
  • JSON-schema validation + 1 retry; cache verdicts per clip_id as the demo fallback
  • Log how often Qwen is called (cost and latency story for the pitch)

Contract

IN unresolved frames + keyframes from P1
OUT verdicts (same segment schema, resolved_by vlm or UNCERTAIN) → P3

Done when

The demo clip gives the same segments 3 runs in a row, the blocked-camera moment comes out grey after Qwen also fails, and the staged no-helmet moment is flagged high.

Nodes 04 · 05 · 06 · Kaizen Core

P3

Backend & Kaizen Engine

Tasks

  • FastAPI app: clip runner, live-watch control, state endpoints, SSE stream, decision endpoint
  • Merge BLIP segments + Qwen verdicts into one timeline per clip
  • Kaizen Engine: cycle time mean + σ (Cpk vs takt when takt is known), VA / NNVA / NVA %, DMAIC Action Cards with ROI formula
  • Alert router: live events go out immediately; high severity pre-empts pending questions
  • Store the operator's language (from the agent or dashboard picker); write alerts + cards in it
  • Agent tool endpoints for P4 (alerts, ack, pending question, verify, briefing)
  • Day 0: publish mock segments.json (with one safety event) so P4/P5 never wait

Contract

IN segments (P1) · verdicts (P2) · tool calls (P4) · decisions (P5)
OUT state + cards + alerts via REST/SSE

Done when

Mock segments go in, cards come out, a verify call reaches the dashboard in under 1 s, and a live high-severity event reaches the voice agent in under 1 s.

Node 07 · Interface

P4

Voice Agent Engineer

Tasks

  • One operator persona (short, polite, hands-free) that replies in the operator's language, across all 70 ElevenLabs languages
  • Three modes: ask, alert, brief
  • Alert mode: high severity interrupts any open question; speak the alert, then ask for a spoken acknowledgement
  • Ask mode opener names the timestamp, e.g. "I saw a 4-second pause at 00:16. Did a part jam?"
  • Map answer → root-cause category (equipment stop, material shortage, …) → verify
  • Hour 1: test STT/TTS for the demo languages (Thai + at least 2 others); set up a fallback

Contract

IN alerts · pending question · briefing (P3)
OUT POST /api/agent/verify · /api/agent/ack (with lang) → P3

Done when

A spoken answer in any demo language turns a grey segment to "verified" in about 3 s, and a high-severity alert is spoken within 2 s of reaching the Orchestrator.

Nodes 00 · 08 · Interface + Stage

P5

Dashboard, Demo & Pitch

Tasks

  • Set up the station camera (live) and film before/after clips: a deliberate long reach, a blocked-view pause, a no-helmet moment
  • SvelteKit app: video + overlay on the left; VA/NVA/grey timeline synced to playback; DMAIC cards on the right
  • SSE via EventSource; red alert banner for safety / critical events
  • Language picker (sets operator lang); card buttons Approve Trial · Dismiss; embedded voice orb
  • 3-min script with a live language switch mid-demo, checkpoint slide, backup screen recording

Contract

IN GET state + SSE (P3)
OUT POST /api/cards/{id}/decision · PUT /api/operator → P3

Done when

The full demo runs end-to-end from cached data, even on bad Wi-Fi.
